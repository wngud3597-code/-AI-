## v0.2.3 다인 화면의 상대 공격 게이지 혼입 수정

사용자 스크린샷의 `Multiple incoming garbage gauges in the selected board`를 공개 클라이언트의 5·6인 DOM 구조로 재현했습니다. 상대가4명 이상이면 왼쪽 `.tetris-metrics` 안에 `.tetris-mobile-opponent-slot`이 들어오며, 내부 상대 게이지도 동일한 class와 `받은 공격 N줄` 라벨을 사용합니다. CSS로 숨겨져 있어도 하위 검색에 포함됐습니다.

내 게이지를 `.tetris-metrics > .tetris-garbage-gauge:not(.is-compact) > .tetris-garbage-gauge-track`로 한정했습니다. 상대 값이 바뀌어도 내 incoming과 fingerprint는 변하지 않습니다. 내 게이지가 없으면 unknown(null)을 유지하며 상대 값으로 채우거나 합산하지 않습니다. 잘못된 내 값이나 실제로 중복된 내 게이지는 계속 오류로 구분합니다.

DOM 회귀19건을 추가했고 수정 전14건 실패, 수정 후 전체321개 테스트 통과를 확인했습니다. Chrome 다인 구조 검사는 `reports/gauge-browser-check.json`에 보존합니다. 스크린샷에는 버전이 없어 수정판 설치 여부는 단정하지 않으며, 최신 설치 시 제목과 F9의 v0.2.3을 확인해야 합니다.

## v0.2.2 시작 실패·자연 낙하 중 탐색 반복 수정

사용자가 제공한 F9 진단은 현재 조각이 없는 DOM 전이 상태였습니다. 시작·탐색 직후·입력 직전의 일시적인 전이만 최대1200ms 동안24ms 간격으로 다시 읽습니다. 다른 방·플레이어·잘못된 보드·일시정지·종료에는 기존 차단을 유지합니다. 영구적인 조각 부재는 원래 오류 문구를 포함해 제한 시간 안에 표시합니다. F9 실패 보고서에도 게임 진행 상태·현재/고스트 레이어 수·고정 셀 수·실행 버전을 남깁니다.

탭 이동이 기존 ERROR나 F9 결과를 STOPPED로 덮어쓰던 문제를 수정했습니다. 실제 실행 중 포커스를 잃으면 중지하며 돌아온 뒤 자동 재시작하지 않습니다. 시작 오류가 사라진 후 수동 재실행이 가능한지도 브라우저에서 검증했습니다.

탐색할 때마다 중력이 진행되어 입력 없이 재계획만 반복하는 조건도 재현했습니다. 보드·큐·HOLD·상태가 그대로이고 현재 조각만 아래로 이동한 경우, 원래 위치와 새 위치에서 모든 회전 후보의 전체 경로를 다시 계산합니다. 매 단계 점유 셀과 최종 착지·잠금 보드·제거 줄이 모두 같은 경우에만 새 관측으로 실행합니다. blocked soft drop·달라진 kick·상단 손실·외부 보드 변화에는 이 재사용을 허용하지 않습니다. 실행 기록의 before/plan은 새 관측에 맞춥니다.

전체302개 테스트(19파일), 타입 검사·빌드 통과. Chrome에서는 조각100ms 부재 후 정상 탐색, 대기 중F8, 시작 오류 보존, 초기20잠금, 탐색6회 모두 자연 낙하 주입 후 신규 검증 배치3회, 공격 복구5경우를 통과했습니다. 브라우저 오류0건, 실제 전송103회와 기록103회 일치. 새 브라우저 로그6개를 before+실제 입력부터 재계산해 분류되지 않은 불일치0건을 확인했습니다. 직접 실제 사이트에서 수정판을 실행한 결과는 아직 없으며 로컬/source/사용자로그 회귀의 범위를 구분합니다.

## v0.2.1 공격 줄 상승 중지 수정

사용자 제공 실제 사이트 표시 로그 3개, 총 370건(정상 배치277, HOLD81, 오류11, 사용자 중지1)을 분석했습니다. 하드드롭 후 중단7건은 줄 제거·공개 큐 전진이 확인되며 실제 보드가 예상 잠금 보드에 공격 줄이 추가된 결과와 정확히 일치했습니다. 이동 중 상승1건, 자연 낙하로 경로가 어긋난3건도 확인했습니다. 파일별 결과는 reports/user-log-audit.json에 있습니다. 세 파일 모두 실행 버전 필드가 없으므로 수정판 실행 여부를 이 로그로 단정할 수 없습니다.

추가 로그 1792725492925의 실패38·70·79번은 각각4·2·4줄 상승이며, 43번은 자연 낙하1칸이 추가된 상태였습니다. 공개 클라이언트 함수로 입력·잠금 결과를 독립 재계산했고 v0.2.1의 복구 조건과 일치했습니다. 추가 사례를 포함한 전체239개 테스트가 통과했습니다. 이번 추가 분석으로 실행 코드를 변경하지는 않았습니다.

수정판은 정확한 상승 패턴과 동일 플레이어·방·조각 전이를 확인하여 이전 경로만 취소하고 재계획합니다. 하드드롭·HOLD 후에는 큐·HOLD 가능 상태·제거 줄 전이도 함께 확인하며 비멱등 입력을 재전송하지 않습니다. 복구 중 추가 공격은 새 보드가 안정된 뒤 다시 계획합니다. F8·잘못된 플레이어·다른 방·설명되지 않는 보드 변화에는 중지를 유지합니다. 일반 보드 예측 일치와 외생 변화 복구를 resynced로 구분합니다.

fixtures/garbage-regression.json에 계정·URL·원본경로·관측시간을 제거한 실제 실패11건을 보존했습니다. tests/runtime/garbage-control.test.ts와 board-transition.test.ts가 사용자 기록, 중력, HOLD, 복구 중 F8·추가 공격·잘못된 세대를 검증합니다. 브라우저 검사는 reports/garbage-browser-check.json: 이동 중1줄, 잠금 직후1·4줄, HOLD직후1줄, 복구 중F8의5경우를 모두 통과했습니다. 일반 복구4경우에서 각3개의 신규 배치가 이어졌고 중복 하드드롭·F8 후 추가 입력은0회였습니다. 실행 코드가 같으므로 이전 브라우저 검사 결과를 유지했습니다.

이 수정 검증은 사용자 기록 재현과 로컬 Chrome에서 수행했습니다. 수정판이 실제 사이트에서 문제를 해결했는지는 새 사용자 기록으로 확인해야 합니다. 아래 단계표·CPU 벤치마크는 이전 초기 검증의 기록이며, 공격량·상쇄·서버 삽입 순서·실전 강도는 계속 unknown입니다. 최신 빌드·테스트 수·해시는 reports/verification.json을 확인하세요.

## 구현

- 실제 userscript 빌드와 내장 Worker, 잠긴 의존성.
- 자기 DOM scope·관전·입력 가능 상태 검증, 엄격한 큐·HOLD·셀 검사, 불변 snapshot.
- bbox↔SRS 변환, 이동·회전·드롭·잠금·제거·spawn, 모호한 방향의 안전한 경로 교집합.
- CPU BFS/beam/HOLD/NEXT, 전역 시간·노드 제한, 조건을 포함하는 transposition key.
- 단일 transaction, 입력별 확인, F8·포커스·채팅·수동 조작·방 변경 중지, 실제 Worker terminate.
- schema2 익명 기록, before와 실제 전송 입력 기반 replay, seed 벤치마크.

공격·spin·상쇄·외생 가비지 순서를 확인한 엔진은 아닙니다. 서버 상태를 직접 수정하거나 React 내부 큐를 읽지 않습니다.
