# 테트리스 AI 실행 안내

설치 파일은 **dist/tetris-ai.user.js** 입니다. Worker는 파일 안에 포함되어 별도 설치가 필요 없습니다. 기존 v4 파일은 보존했습니다.

**현재 설치판 v0.2.3:** 기존 Tampermonkey 스크립트를 이 파일로 교체·저장하고 게임 페이지를 새로고침하세요. 패널 제목에 v0.2.3가 보여야 합니다. 5·6인 화면에서 내 정보 패널 안에 들어오는 상대 미니 보드의 공격 게이지를 제외하고 내 게이지만 읽습니다. `Multiple incoming garbage gauges in the selected board` 오류를 일으키던 범위 선택을 수정했습니다. 제목에 버전이 없으면 이전 판이 실행 중인지 확인하고, 중복 등록된 테트리스 AI 스크립트는 하나만 활성화하세요.

v0.2.2의 시작·낙하 수정도 포함합니다. 조각 생성·고정 중 일시적으로 조각이 없으면 최대1.2초 기다려 다시 읽습니다. 탐색 중 자연 낙하만 발생했다면 모든 회전 후보에서 경로와 착지 결과를 재검증한 뒤 실행하여 탐색만 반복하는 현상을 줄였습니다. 탭을 옮겨도 원래 오류와 F9 진단은 유지하며, 실제 실행 중 탭 포커스가 사라지면 중지합니다. 기록과 F9에 실행 버전·게임 상태를 포함합니다.

v0.2.1의 공격 줄 복구도 포함합니다. 보드 상승이 정확한 가비지 형태로 확인되면 이전 경로를 버리고 현재 보드에서 재계획합니다. 이미 보낸 하드드롭·HOLD는 다시 보내지 않습니다. Tampermonkey 보안 설정을 바꿀 필요는 없습니다.

## 바로 실행하기

1. 상위 작업 폴더의 **실행.cmd** 를 더블클릭하면 로컬 연습 화면이 열립니다. AI 패널의 **연속 실행**을 누르면 움직입니다. 공개 클라이언트 물리를 사용한 합성 환경이며 실제 사이트 서버와 연결되지 않습니다.
2. 실제 사이트에서는 Chrome/Edge의 Tampermonkey에서 새 스크립트를 만들고 **dist/tetris-ai.user.js 전체 내용**을 붙여넣어 저장합니다. 확장이 설치되어 있으면 [로컬 설치 링크](http://127.0.0.1:8765/tetris-ai.user.js)도 사용할 수 있습니다.
3. 브라우저 확장 설정에서 userscript 실행을 허용하고 기존 v4와 다른 테트리스 자동 조작 스크립트를 비활성화합니다. 이번 작업에서는 확장 설치·등록을 자동 수행하지 않았습니다.
4. [부리부리랜드](https://buriburiland.com/)에서 본인의 1인 연습 게임을 시작합니다. 게임 시작 버튼은 사용자가 누릅니다. 새로고침하면 오른쪽 아래 AI 패널이 표시됩니다.
5. **F9 상태 점검**으로 public-dom, display-only, 20행 보드·현재 조각·NEXT 5개와 입력 활성 상태를 확인합니다. 메인 보드가 여러 개면 **내 보드 선택**으로 자기 보드를 클릭합니다. 관전 보드는 제어하지 않습니다.
6. **관측·탐색만 → 한 수 실행 → 연속 실행** 순서로 확인합니다. 관측·탐색만은 게임 키를 보내지 않습니다. HOLD가 선택된 한 수는 HOLD만 실행하고 끝납니다. 다음 배치는 새 관측에서 계획합니다.
7. **F8** 또는 **중지**는 Worker를 종료하고 눌린 키를 해제합니다. 중지 처리 뒤 새 keydown을 시작하지 않습니다. 이미 보낸 입력은 취소할 수 없습니다. 탭 전환·채팅 포커스·직접 조작·게임 종료·방 변경 때도 중지합니다.
8. 문제가 생기면 **검증 기록 저장**으로 JSONL을 저장합니다. 보드·입력·예측·관측 결과만 기록하며 URL·닉네임·비밀번호·쿠키를 수집하지 않습니다. 마지막 1,000개 기록을 메모리에 유지하므로 긴 세션은 중간에 저장하세요.

로컬 서버는 127.0.0.1:8765에만 바인딩하며 npm.cmd start로도 실행할 수 있습니다. 설치 링크 요청마다 최신 빌드를 읽습니다. 데모에는 자동 중력·서버·상대가 없습니다. Chrome 회귀 검사에서는 탐색 중 낙하를 별도로 주입하지만 실제 경기 속도나 lock deadline 검증으로 해석하지 않습니다.

## 개발 환경과 명령

실행 환경: Windows x64 10.0.26200, Intel i7-11700, 논리 CPU 16개, RAM 32GiB, Node **24.18.0**, npm **12.0.1**, Chrome. API 키·GPU는 사용하지 않습니다.

PowerShell에서 프로젝트 폴더를 열고 실행합니다. 실행 정책 문제를 피하도록 npm.cmd를 사용합니다.

verify:source, test:browser, 데모는 원본 공개 JS 캐시 ../.cache/buriburiland-public-2026-10-23/847.a5a05f14ceb3f87d.js를 사용합니다. 이 작업 폴더에는 캐시가 있습니다. 다른 PC에서는 [고정 원본](https://buriburiland.com/_next/static/chunks/847.a5a05f14ceb3f87d.js)을 같은 위치에 저장해야 하며, SHA256이 다르면 검사를 중단합니다. 공개 사이트 코드와 React는 배포 userscript에 포함하지 않습니다.

replays/synthetic-example.jsonl은 정상·의도한 불일치·취소를 포함한 예제입니다. 재생 시 불일치 1건을 검출하고 종료 코드 1을 반환하는 것이 정상입니다. replay는 before와 실제 기록 입력부터 다시 계산하며 저장된 expectedBoard를 정답으로 쓰지 않습니다. 타임스탬프 순서는 검사하지만 자연 중력·lock 시간·외생 가비지를 완전 재현하지는 않습니다.

## 현재 구현과 한계

실행 경로는 src/userscript/main.ts → runtime/dom.ts → runtime/worker-client.ts → runtime/worker-entry.ts/engine.ts → runtime/control.ts입니다. 기존 interface와 React 어댑터는 회귀 참고용으로 남아 있으며 새 userscript에서 사용하지 않습니다.

동일한 자기 stage 안에서 고정 셀 200개·현재 조각 4셀·HOLD·공개 NEXT를 동기적으로 읽습니다. 실제 셀 좌표로 bbox 원점을 복원합니다. I/S/Z의 구분 불가능한 방향은 후보로 유지하며 모든 후보에서 같은 셀 결과를 내는 경로만 사용합니다. 제어 중 확인한 spawn/입력 이력은 방향 기억에 쓰고 중지·보드 보정·재시작 때 폐기합니다. 서버 revision이나 비공개 미래 큐를 만들거나 읽지 않습니다.

탐색은 현재 pose에서 시작하는 BFS와 같은 도달 가능성 모델을 후속 조각에도 쓰는 제한된 beam search입니다. 시간·노드 예산을 모든 깊이가 공유하고 얕은 결과를 유지합니다. 최대 깊이 설정이 항상 완료된다는 뜻은 아닙니다. 실제 완료 깊이·노드를 패널과 기록에 남깁니다.

입력은 window 하나에 keydown/keyup을 보내며 기본 키 간격은 45ms 이상입니다. 확인되지 않은 이동은 진행하지 않고 HOLD/하드드롭을 재전송하지 않습니다. 잠금 후 표시 보드·제거 줄·공개 큐를 비교합니다. DOM은 서버 응답 전 예측 상태도 표시하므로 **display-match는 서버 확정 일치를 뜻하지 않습니다**.

현재는 생존·줄 제거·구멍 접근 비용 중심 엔진입니다. 180도 회전, all-spin 공격 판정, combo/B2B 공격량, 가비지 상쇄·송신·삽입 순서는 실전 기능에서 비활성 또는 unknown입니다. 받은 줄이 이미 반영된 보드에서 탐색하며, 실행 중에도 기존 보드가 정확히 위로 이동하고 한 칸 구멍인 행들이 아래에 추가된 변화는 새 관측에서 재계획합니다. 몸체 불일치·상단 점유 블록 손실·잘못된 플레이어·불명확한 하드드롭 결과에는 중지합니다. 복구 기록은 resynced로 분리하고 서버 삽입이나 공격 예측 정확도로 세지 않습니다. 반격 AI·인간 상대 우위·실게임 1,000잠금 승인 기준은 달성하지 않았습니다.
